# Instruction: Backend - Allow Multiple Meals Per Time Slot

## Feature

- **Summary**: Lift the 1:1 constraint between (Date, MealType) and Recipe so users can add multiple dishes to the same meal slot (e.g., main + side for Dinner). Only prevent the same recipe from being added twice to the same slot.
- **Stack**: `.NET 9`, `C# 13`, `EF Core 9`, `PostgreSQL 17`, `xUnit`, `FluentAssertions`
- **Branch name**: `feature/multiple-meals-per-slot`
- **dependencies**: none

## Implementation phases

### Phase 1: Database Migration

> Drop the unique (date, meal_type) index and replace it with (date, meal_type, recipe_id) to allow multiple meals per slot while preventing duplicate recipes.

> Rule: EF Core migration only. Do not change domain entity structure.

1. Update `MealPlannerDbContext.ConfigurePlannedMeal` unique index configuration
   1.1 Replace `HasIndex(m => new { m.Date, m.MealType }).IsUnique()` with `HasIndex(m => new { m.Date, m.MealType, m.RecipeId }).IsUnique()` — commit: `refactor(db): replace slot unique index with slot+recipe unique index`
2. Generate EF Core migration
   2.1 Run `dotnet ef migrations add AllowMultipleMealsPerSlot` — commit: `feat(migration): allow multiple meals per time slot`

### Phase 2: Repository Layer

> Update repository interface and implementation to return lists instead of single meals for date+mealtype queries.

> Rule: Keep `GetByDateAndMealTypeAsync` method name but change return type. Add new method for duplicate-recipe check.

1. Update `IPlannedMealRepository` interface
   1.1 Change `GetByDateAndMealTypeAsync` return type from `PlannedMeal?` to `IReadOnlyList<PlannedMeal>`
   1.2 Add `GetByDateMealTypeAndRecipeAsync(DateOnly date, MealType mealType, Guid recipeId)` returning `PlannedMeal?` — commit: `refactor(domain): update IPlannedMealRepository for multi-meal slots`
2. Update `EfCorePlannedMealRepository` implementation
   2.1 Change `GetByDateAndMealTypeAsync` to use `ToListAsync()` instead of `FirstOrDefaultAsync()`
   2.2 Implement `GetByDateMealTypeAndRecipeAsync` with `FirstOrDefaultAsync` filtering on all 3 fields
   2.3 Remove the duplicate-check guard in `AddAsync()` that throws `InvalidOperationException` — commit: `refactor(infra): update EfCorePlannedMealRepository for multi-meal slots`

### Phase 3: Application Layer

> Update command handler to allow adding to occupied slots (only block duplicate recipes) and update weekly plan DTOs to return lists.

> Rule: ErrorOr pattern. No exceptions for business logic.

1. Update `MealErrors`
   1.1 Remove `SlotAlreadyFilled` error
   1.2 Add `RecipeAlreadyInSlot(DateOnly date, string mealType)` returning `Error.Conflict` — commit: `refactor(app): replace SlotAlreadyFilled with RecipeAlreadyInSlot error`
2. Update `AddRecipeToMealPlanCommand` handler
   2.1 Replace `GetByDateAndMealTypeAsync` + `SlotAlreadyFilled` check with `GetByDateMealTypeAndRecipeAsync` + `RecipeAlreadyInSlot` check — commit: `feat(app): allow adding multiple meals to same slot`
3. Update `WeeklyPlanDto` / `DayPlanDto`
   3.1 Change `Breakfast`, `Lunch`, `Dinner` fields from `WeeklyMealDto?` to `IReadOnlyList<WeeklyMealDto>` — commit: `refactor(app): update DayPlanDto to list-based meal slots`
4. Update `GetWeeklyPlanQuery` handler
   4.1 Update mapping logic to group meals by mealtype into lists instead of picking single values — commit: `refactor(app): update GetWeeklyPlanQuery handler for multi-meal slots`
